# 工程接入与验证

在实现特效或排查正式技能与表现不一致时阅读。这里描述需要建立的契约，不要求工程存在指定类名、目录、对象池或文档。

## 定位最小接入链

先确认 Unity 版本、Built-in／URP／HDRP、目标平台、镜头及资源加载方式。只读取受影响的技能和表现链路；已有项目约束优先决定组织方式。

| 接入点 | 要确认的事实 |
| --- | --- |
| 技能配置 | 真实目标、投放方式、有效范围与阶段；表现读取解析后的值，避免重复应用倍率 |
| 正式事件 | 准备成功、释放、到达、实际命中、持续更新、取消与结束分别在哪里发生 |
| 空间数据 | 谁提供位置、方向、挂点与路径；目标移动、死亡或来源失效后如何处理 |
| 资源装配 | Shader、网格和材质从哪里加载，如何被场景或构建依赖收录 |
| 时间与归属 | 暂停、倍速、局部冻结、场景退出，以及持续效果的真实状态或任务归属 |
| 旧表现 | 新主体是否与通用施法、逐目标命中或旧区域主体重复；替换后是否仍有正式消费者 |

接入顺序通常是“正式事件 → 准备视觉依赖 → 配置空间与时间 → 启用 → 根据状态更新 → 结束并清理”。这只是契约，不应为了符合顺序另造技能执行框架。没有现成事件时，在真实执行边界增加最小表现通知；分析任务或仅有参考图时只描述所需契约，不虚构生产接口。

视觉通知不结算伤害、费用或控制，不把预测、预警或动画高峰当作命中事实。一个实际区域事件生成一次主体，逐目标命中可补局部反馈；多段与持续效果跟随真实事件，不另建伤害时间轴。替换旧入口前核对运行时调用、资源序列化与生命周期引用。

## 资源、时间与复用

- 使用工程已有装配方式；没有加载系统时采用满足本次效果的场景／Prefab 序列化引用或现有资源接口，不引入整套管理框架。新 Shader 和网格须有实际引用与构建收录路径，不能仅因编辑器中可查找就认为发布可用。
- CPU 动画、粒子、拖尾和 Shader 流动须遵循一致的暂停、倍速与冻结语义。需要局部时间时显式传入视觉年龄或阶段，不直接依赖持续推进的全局时间。视觉随机独立于影响玩法结果的随机源。
- 有对象池时复用并重置来源、目标、时钟、属性块和粒子；没有对象池时按效果频率与成本决定是否需要。取消、来源失效、场景卸载及再次启用都应清理活动登记和实例状态。
- 按预期同屏数量评估材质变体、几何、粒子、程序场计算、透明屏幕覆盖与重叠。复用缓存并控制容量；超预算优先省略装饰，保留必要的区域边界和主轮廓。低档保留语义，不为所有工程规定同一数量上限。

## 验证选择与交付范围

采用目标工程已有的验证入口，不要求固定 SDK、编译器路径或特定 Unity 缓存结构。验证产物遵循工程约定；没有约定时放到临时目录并清理。纯 skill 文档修改只验证 skill 结构与内部引用，无需编译游戏。

| 层级 | 可验证内容 | 不代表什么 |
| --- | --- | --- |
| 调用链审查 | 正式事件、目标数据、取消和资源归属是否接上 | 不能证明实际渲染正确 |
| C# 编译 | 源码与程序集引用是否通过编译 | 不覆盖 Shader、导入或运行时几何 |
| 几何边界检查 | 生产几何输出是否有限、索引有效及端点是否符合设计 | 不覆盖镜头观感或 GPU 成本 |
| 代码离线图片预览 | 当前几何、顶点数据与移植材质公式在指定镜头／阶段下的近似观感 | 未执行 Unity Shader，不覆盖导入、管线、透明排序或实机性能 |
| Unity 导入／构建 | 材质、Shader 变体与资源依赖在目标环境是否有效 | 不自动证明还原度与性能 |
| 实际渲染 | 代表阶段、转向、遮挡、重复使用、低档及同屏重叠 | 单个镜头不代表全部平台与场景 |

按变更选择必要检查：修改 C# 做适用编译；修改几何覆盖实际受影响的端点或退化情况；修改 Shader 与资源时检查目标环境的导入或构建（可执行时）。允许运行时优先验证首次创建、再次复用、取消和代表阶段，避免无关全库检查。

Editor、PlayMode、截图或构建受限时，继续完成可执行的审查与检查，并明确未覆盖的环节；不绕过环境限制，也不把画面反馈作为所有交付的前置条件。没有工程时交付参考图分析、素材需求和接入方案；没有实际渲染时标明“实现已接入，视觉还原未验证”。

用户需要在对话中看效果时，可按 [代码驱动的图片预览](code-image-preview.md) 交付离线图片；它补充视觉讨论，不能把验证级别提升为实机验收。
