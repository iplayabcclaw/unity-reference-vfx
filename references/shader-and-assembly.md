# Shader 与特效装配

用于实现或深入分析材质时阅读。以下是设计方法，不是可直接复制的完整 Shader，也不限定所有效果使用同一技术。

## 从介质选择载体

先确定参考图中承担识别的形状与运动，再选择载体。以下是按表现需求选择的方法，不能按技能名称固定结构，也不要求每招都具备全部层。

| 表现需求 | 优先考虑的载体 | 要先确定的量 |
| --- | --- | --- |
| 稳定表面、切面或明确厚度 | 立体／曲面网格，配合表面材质 | 轮廓、厚度、法线、局部形变 |
| 翻卷、扩散或不断变化的松散介质 | 网格粒子、闭合体、动态曲面与程序密度场 | 发射分布、单元轮廓、密度、速度与寿命 |
| 沿方向或路径连续流动 | 条带、线段网格、拖尾，局部粒子补细节 | 路径、宽度变化、分段密度、流向 |
| 薄层、壳面或贴地分布 | 曲面／壳面／贴地网格，配合直接计算的程序材质 | 表面法线、真实边界、与承载面的间隔 |

混合介质按职责拆层：主体承担轮廓与主要运动，细节提供内部变化，伴随层表达烟尘、碎屑或余韵。仅保留参考图需要的层；不能用亮点堆积代替连续主体，也不能把所有流体压成带亮边的斩面。先用低细节版本落实参考图的轮廓、比例、空隙和遮挡，再补内部素材和装饰；有画面条件时核对投影，没有条件时明确这些仍是实现假设。图像指标、素材选择与配方字段见 [参考图还原与分层配方](reference-fidelity.md)。

宽面翻卷气流的具体网格、材质、运动与成本见 [翻卷纤维气流代码参考](folded-airflow-reference.md)。该参考只提供几何与运动代码；材质必须直接计算内部结构，不采样贴图。

地面连通龟裂、放射主裂隙与中央小碎块的半平面裁切、共享边、二级细分和径向高度算法见 [龟裂与中央碎岩算法](ground-fracture-reference.md)。

## 建立与介质一致的坐标

坐标要表达实际流向、密度变化与边界，不默认 `U` 是尾到尖端、`V` 是刃背到切缘。

| 载体 | 坐标依据 |
| --- | --- |
| 曲面或条带 | 沿曲线／路径的距离与横向宽度；需要时另存高度或厚度 |
| 立体表面或壳面 | 稳定表面 UV、物体空间位置或法线；球面接缝需避免明显跳变 |
| 粒子单元 | 局部 UV 表达单元轮廓，归一化年龄控制形变与退场，独立相位打散同步变化 |
| 区域介质 | 发射源局部坐标或稳定世界坐标，表达高度、径向距离、轴向与空间密度 |

随源移动的效果通常使用局部空间；留在场景中的余迹使用世界空间。按真实规则决定粒子是否继续跟随源，不让相机转动改变流向、发射分布或范围。程序细节分布与流动速度按长度计量，避免尺寸改变后内部结构被拉伸或速度失真；明确用户要求固定形状时，不能通过敌我距离反算缩放。

宽斩面、弯月等稳定弧形轮廓可使用带曲率的网格，表达长度、端部收尖、弧腹深度、截面拱起及内外缘变化。这类斩面可约定 `U` 沿尾到尖端、`V` 横跨刃背到切缘，用于定向流纹与刃光。曲率按相对端点弦线的偏离判断；两缘曲率不同时分别定义曲线再插值，不翻转整个网格连带颠倒附着层。

## 材质功能拆分

| 功能 | 常用方法 | 注意 |
| --- | --- | --- |
| 内部流纹 | 直接计算的定向解析场、程序噪声与顶点动画 | 翻卷和拉丝需要明确结构，均匀噪声不能代替真实形态变化 |
| 扰动 | 数学函数生成有符号向量场 | 仅改变指定细节或顶点，不改写必要轮廓 |
| 透明形状 | 解析遮罩、坐标柔边、顶点 Alpha | 不依靠亮度同时决定所有透明区域 |
| 侵蚀退场 | 噪声场与阶段阈值 smoothstep | 端点必须能彻底退场，不要留下透明矩形和随机硬洞 |
| 局部高亮 | 解析遮罩、程序密度／高度场或表面响应＋HDR 颜色 | 位置由介质决定；只有需要切缘的斩面使用刃光，避免整片泛白 |
| 薄膜翻卷 | 实际曲面形变＋程序场流动 | 扩展包围盒容纳位移；避免位移改变真实判定 |
| 实体碎片 | 有切面的立体网格与明暗材质 | 不透明材质不能靠 Alpha 自然淡出，可缩小或侵蚀 |

几何轮廓、程序密度、扰动和发光应能独立调整。全部字段由坐标、顶点数据和局部时间直接计算，不使用图片、噪声贴图、流向图或序列帧。缺少卷曲、分叉或破碎结构时，按 [素材选择](reference-fidelity.md#生产素材选择) 补充相应网格与动画，不只增加粒子和噪声。
片元设计示意：

```text
flow = proceduralVectorField(coordinates, localTime)
movingUV = uv * tiling + phase * speed + flow * distortion
field = combine(proceduralNoise(movingUV), proceduralNoise(detailUV))
shape = analyticShape(coordinates)
erosion = threshold(field, dissolve)
alpha = shape * erosion * lifetimeOpacity
body = palette(field)
highlight = mediumHighlightMask(coordinates, field, detail)
color = body + highlightColor * highlight * localEmission
```

这是适用于流动透明介质的一种组合示意，网格实体或其他无贴图载体不必全部使用这些步骤。高亮遮罩可来自切缘、密集核心或局部脉冲，具体颜色、噪声权重、溶解方向由参考图和当前 Shader 决定。不要把示意当生产函数，避免复制项目已有伤害或资源管理逻辑。

## 混合、发光与明暗

- 暗色腹面、血膜、烟雾通常先考虑普通透明混合。窄刃光、火星等可使用加法，或在同一透明表面输出局部 HDR。
- 无光照材质保持亮度不依赖场景灯光，但并不自动产生外扩光晕。
- HDR 输出提供高亮，Bloom 在后处理中扩散它们，加法使重叠处增亮。三者作用不同。十六进制 RGB 只表达基础色，不表达 HDR 强度；配方应另写线性 RGB／发光倍率，并核对项目的颜色转换、曝光与色调映射，不能把图片取色直接当 Shader 最终输出值。
- Bloom 不是动态灯，不等于照亮人物和地面。参考图的环境受光若不能在当前项目实现，明确区别，不虚称完成。
- 先把关闭 Bloom 时的轮廓、暗部和主色做清楚，再用泛光增强；别用调高全局 Bloom 弥补单招材质问题。
- 使用现有共享发光函数时，核对是否已增强 HDR，避免又叠一遍高倍乘法。
- “去亮点但保留紫色”应冻结认可的配色，沿当前材质查找尖端、切缘、闪烁、粒子和公共高光的独立贡献，关闭对应局部亮部；只压暗底色会改变颜色却保留亮点。叠加技能的截图不能直接证明每个亮点归属，未确认时区分推断与事实。
- “隐隐呼吸”用正式局部时钟驱动整层小幅平滑明暗，不沿 UV 生成移动亮斑；“稍微亮一点”调主体中间调，避免重新加回已移除的闪点。周期、幅度和颜色按当前反馈确定，不沿用某一技能的固定值。
- “气雾浓一点”优先调连续密度、透明覆盖与径向厚度。程序密度、顶点 Alpha、横向柔边和实例透明度相乘可能把高透明度削成细纤维；核对最终覆盖，必要时增加错开的雾面或浓雾专属分支，保留上下消散与暗部，而非提高发光。使用公共材质时限制修改范围，避免改变其他技能。
- 透明曲面常用双面、关闭深度写入、保留深度测试；以当前遮挡与排序需求决定，不能靠 ZTest Always 让技能穿透所有人物解决摆放问题。
- 网格粒子按真实流向或几何轴线摆放，禁止用朝镜头的图片面片。多层透明排序与柔边须核对当前管线；不得引入深度贴图采样绕过无贴图约束，没有对应能力时不承诺体积渲染。

## 程序网格的数值边界

生成曲面时核对分数次幂、平方根、归一化与除法的输入范围，并处理端点及退化段。数学上非负的表达式也可能因浮点误差略小于零，例如 `sin(π × v)` 的端点；只有按公式语义应非负时才在运算前钳制，不以任意夹值掩盖坐标或参数错误。零长度方向应使用稳定备用轴或按几何规则处理退化段。

在生成或上传边界确认顶点、法线、UV 与包围盒使用的值有限；发生 NaN／Infinity 时定位首个非法计算及其输入，而不是删除坏顶点、吞异常或只换一个包围盒继续上传。静态或缓存网格在构建边界检查结果；动态网格在生成公式处约束输入并定位非法输出，避免另加每帧全网格扫描。按项目许可做相关编译或边界验证，C# 编译通过本身不能证明运行时网格有效。

## 初始化、装配与生命周期

沿正式入口按以下顺序核对；复用项目已有资源和缓存，不另建一套加载或管理入口。

1. **初始化资源。** 静态字段和 MonoBehaviour 实例字段初始化仅保存托管数据、空引用或序列化配置。`MaterialPropertyBlock`、`Material`、`Mesh` 等需要 Unity 原生运行时的对象，在 `Awake`、`OnEnable` 或明确由主线程调用的初始化方法内创建，属性 ID 也在该阶段缓存。选择符合资源寿命的回调，并处理重新启用／脚本重载后的绑定；不能假定缓存复用会消除构造时机限制。
2. **装配材质。** 绑定实际网格／粒子、无贴图 Shader 和有限材质变体，再写入属性块。复用上色、发光或材质辅助函数前读取其实现，确认是否会替换 `sharedMaterial`、切换 Shader／关键字或清空 PropertyBlock；专用材质使用保留自身 Shader 的写入路径。按上方配色表核对最终输出，而非只看创建时传入的颜色。
3. **完成初始化后启用。** 从池中取出到全部依赖就绪期间，阻止更新和绘制消费半初始化对象；成功后再登记活动实例并启用。失败时清理已创建资源、活动登记和任务归属，按池约定回收或销毁，并保留原始异常。缺失资源须明确诊断；不要用空判断跳过绘制、吞异常或替换默认材质隐藏失败。
4. **由正式事件驱动。** 生成、维持、命中与退场读取真实位置和生命周期，装饰层可有不同寿命但不额外结算。持续场主体创建一次，真实跳伤仅加强局部反馈；弹体尾迹采样实际轨迹。分开单元年龄、相位与发射间隔，遵循目标工程的暂停、倍速和局部冻结规则；着色器运动与 CPU 动画使用一致的视觉时间来源，不默认全局 Shader 时间符合技能规则。
5. **回收与复用。** 区分停止发射和清除已有单元，按技能规则处理取消、来源失效和短暂余韵；必要范围提示随真实区域结束。再次租借时重置来源身份、时钟、材质分支、属性块、粒子和拖尾，避免上一用途残留。引用丢失时先重绑存活子对象，再补建确实缺失的资源，不能生成重复主体；共享缓存只由其所有者释放。

材质种类、网格和粒子缓冲保持有界，避免逐帧分配。低特效先保留主轮廓、主色与必要范围提示，再减少装饰；性能同时考虑屏幕覆盖、透明重叠、采样量和粒子数。

## 排错与验证

运行异常先找同一调用链中的**第一条异常**及完整堆栈，沿初始化到首次使用定位原因；后续空引用可能只是初始化中断的结果。缺少首条异常时，明确诊断尚未确定，清理半初始化实例只能算阻止连锁报错，不能宣称根因已修复。

按 [差异修正流程](reference-fidelity.md#差异修正) 先确定问题属于挂点、朝向、轮廓、尺寸、素材、亮度还是时序，再修对应变量。空间问题优先核对坐标系、镜头投影与锚点；颜色问题先核对最终材质与属性写入，再追踪 Shader、混合和后处理。

验证遵循项目许可并通过正式入口覆盖本次受影响的首次创建、复用或失败路径；不以源码字符串检查替代行为验证。允许渲染时检查实战镜头里的轮廓、主色和明暗层次，按需检查重叠和低特效档。交付区分调用链审查、C# 编译、Shader 导入／编译与实机观感；未执行的环节明确列出，不以快速编译通过推断渲染正确。
